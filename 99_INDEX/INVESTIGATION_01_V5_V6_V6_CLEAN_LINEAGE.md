## 5. User challenge and corrective methodology

The subsequent methodological challenge identified that an API
success was being treated as a valid scientific observation even
when the extracted model response was empty.

A valid call is not automatically a valid response measurement.

The V6 Clean corrective protocol preserved:

- Frozen prompts
- Experimental conditions and seeds
- Feature definitions
- Contrast definitions
- Classifier/statistical design

The execution protocol changed:

- Response extraction added content-based fallback handling.
- Empty extracted responses became invalid.
- Invalid responses were retried.
- Retry allowance increased from 5 to 8.
- Reasoning effort was explicitly set to none.

The last point is a confound for causal attribution:
the correction changed both validity handling and execution
configuration.

Therefore changes between the original and clean runs cannot be
attributed exclusively to empty-response handling.
